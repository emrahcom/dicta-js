# Dropped final

A final still awaited on a connection the element closes itself is dropped
without a failure shown (`architecture.md`, Connection). Today the count of
awaited finals is reset only when the server or the network closes the
connection, so after the element closes one itself the count stays too high: a
later, normal close of the new connection shows that voice failed.

`src/input.ts`: the count of awaited finals is set to 0 where the element closes
a connection itself: when `server` or `lang` changed at the next start, and when
the element is removed from the page.

Tests (browser): a hold utterance ends and, before its final arrives, `lang`
changes and the next press opens a new connection; that utterance gets its
final; when the server then closes the new connection while it is idle, no
failure is shown.

Check: `npm run check`, `npm run lint`, `npm run test`, `npm run test:browser`
and `npm run build` pass.
